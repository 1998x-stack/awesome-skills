# 反模式警示录

## 10 大 Prompt 反模式与修正

### 1. 否定式指令堆积

**症状**：Prompt 中 "不要/不能/禁止" 出现超过 5 次，超过正向指令比例
**问题**：模型需要消耗更多注意力处理禁止项，正向行为反而模糊

```
❌ 反模式：
不要使用复杂词汇，不要超过 200 字，不要使用列表，
不要提及价格，不要建议竞品...

✅ 修正：
用简单词汇，控制在 150 字以内，以段落形式，
聚焦产品本身的核心价值...
```

---

### 2. 过度工程化

**症状**：Prompt 超过 3000 字但质量未明显提升，甚至下降
**问题**：冗余指令稀释了关键信息；token 浪费

```
修正原则：
- 用 1 个好示例替代 200 字描述
- 删除所有"请注意"、"务必记住"等修辞性强调
- 使用结构化 XML 标签，信息密度 > 文字堆砌
```

---

### 3. 字段定义模糊

**症状**：同样的 Prompt 在不同上下文产生语义不同的输出
**问题**：字段名在不同业务场景下含义不同，模型只能猜测

```
❌ 反模式：
输出包含 difficulty 和 analysis 字段

✅ 修正：
【字段定义】
- difficulty：easy/medium/hard 三档，反映题目综合思维深度
- analysis：解释解题原理和方法（非评分标准）
```

---

### 4. 硬编码条件逻辑

**症状**：Prompt 包含 "如果 X 则 Y，否则 Z" 的大量分支
**问题**：维护困难，模型对复杂条件的处理不稳定

```
❌ 反模式：
如果用户是初学者，使用简单语言；
如果用户是专家，使用专业术语；
如果话题是数学，给出公式；
如果话题是历史，给出时间线...

✅ 修正：
提取 category variables，使用模块化注入：
{difficulty_module} + {domain_module}
逻辑在代码层处理，Prompt 保持干净
```

---

### 5. 无示例的复杂格式要求

**症状**：详细描述了期望格式，但模型依然输出错误格式
**问题**：文字描述格式远不如实际示例有效

```
❌ 反模式：
请以 JSON 格式返回，包含 name 字段（字符串），
score 字段（0-100 整数），tags 字段（字符串数组），
每个 tag 不超过 5 个字...

✅ 修正：
请按以下格式返回：
{"name": "示例名称", "score": 85, "tags": ["标签一", "标签二"]}
```

---

### 6. 忽视上下文污染

**症状**：长对话中模型逐渐"忘记"初始规则，行为漂移
**问题**：早期指令在长上下文中权重降低

```
修正策略：
1. 每 10 轮对话重注入核心规则（<3 行精简版）
2. 实施 Compaction：每 50K token 生成压缩摘要并重置
3. 关键约束在 System Prompt 中不可删除，仅对话历史可压缩
```

---

### 7. 单次测试即上线

**症状**：基于 2-3 次手动测试就认为 Prompt 已优化完成
**问题**：LLM 存在随机性，小样本无法代表真实分布

```
最低标准：
- 建立 20 条测试用例（60% 标准 + 25% 边界 + 15% 对抗）
- 每个 Prompt 版本至少运行 3 次取平均
- 使用 LLM-as-Judge 进行自动化评估
```

---

### 8. 流式输出无 Order 字段

**症状**：前端无法判断流式输出是否完整，调试困难
**问题**：JSONL 流没有顺序追踪字段

```
❌ 反模式：
{"type": "analysis", "content": "..."}
{"type": "recommendation", "content": "..."}

✅ 修正：
{"order": 1, "type": "analysis", "content": "..."}
{"order": 2, "type": "recommendation", "content": "..."}
```

---

### 9. 角色通胀

**症状**："你是世界上最权威的、最聪明的、最专业的..."
**问题**：夸张角色无实质提升，可能让模型"自我约束放松"

```
❌ 反模式：
你是全世界最顶尖的 AI 助手，拥有超人般的智慧...

✅ 修正：
你是一位拥有 10 年经验的法律顾问，专注于合同纠纷领域，
曾处理过 500+ 件商业合同案例。
（具体、可信、有边界）
```

---

### 10. 假设共享上下文

**症状**：Prompt 引用"之前讨论的方案"、"你知道的那个项目"
**问题**：每次 API 调用都是无状态的新对话

```
❌ 反模式：
基于我们之前谈到的架构，继续优化...

✅ 修正：
基于以下架构设计（以下是完整描述）：
[完整架构信息]
请继续优化...
```
