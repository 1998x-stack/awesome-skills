# 模型适配策略详细参考

## Claude (Anthropic)

**核心特性**：长文推理强、谨慎精确、善于遵循复杂指令

### 专项技巧

**XML 标签结构化（最高效）**
```xml
<context>背景信息</context>
<task>具体任务</task>
<output_format>输出格式</output_format>
```

**Prefill 技术（跳过前言）**
```python
messages=[
    {"role": "user", "content": "分析以下数据..."},
    {"role": "assistant", "content": '{"result":'}  # 预填充
]
```
效果：强制跳过"当然，我来分析..."等前言，直接输出 JSON。

**显式目标声明**
- 需要"超出预期"的输出时，必须明确说："请提供超越基本要求的深度分析"
- 不要期望模型自行推断"above and beyond"意图

**批判反思步骤（可选）**
```
在得出结论前，请：
1. 列出所有不确定假设（置信度 < 0.8）
2. 考虑一个与主要观点相反的视角
```

**长文档定位锚点**
对于 50K+ token 文档，在查询中直接引用关键句：
```
"在文档中提到'[关键句片段]'的那一段，..."
```

## GPT-4o / GPT-4 (OpenAI)

**核心特性**：结构化输出稳定、代码生成强、对数值约束响应好

### 专项技巧

**精确数值约束**
```
❌ 给几个要点
✅ 给恰好 3 个要点，每点不超过 15 字
```

**格式提示位置**
- 格式约束放在 User Turn 末尾效果优于 System Prompt
- 示例："请以 JSON 格式返回，不含其他文字"

**Structured Outputs API**
对于 API 使用者，启用 `response_format: {"type": "json_object"}` 比提示词约束更可靠。

## Gemini (Google)

**核心特性**：多模态处理强、长上下文管理好、数学验证能力强

### 专项技巧

**多模态输入标注**
```
请分析以下 [图片/表格/代码/音频 - 明确指定类型]：...
```

**数学步骤验证**
```
请在得出数值结论前，展示完整计算过程，
并进行一次独立的验证计算以确认结果。
```

**引用来源请求**
```
如果你的回答基于特定的知识或研究，请标注来源类别
（如"基于统计学原理"、"基于文档中第X节"）。
```

## 通用适配原则

```
1. 保持 CRISP 骨架不变
2. 仅调整语法偏好（XML vs Markdown vs 纯文本）
3. 数值约束精确程度因模型而异
4. 始终在目标模型上实际测试，文档描述可能滞后于模型更新
```
