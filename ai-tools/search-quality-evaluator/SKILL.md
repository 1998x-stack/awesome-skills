# Search Quality Evaluator Skill

基于 Google Search Quality Evaluator Guidelines（SQEG，2025年9月最新版）构建，用于系统性评估多篇搜索文章内容的质量，输出结构化评分报告。

## 核心评估框架

本技能依据 SQEG 两大评估维度展开：

### 维度一：页面质量（Page Quality, PQ）

评估**内容本身的质量**，不考虑与特定查询的匹配度。

### 维度二：需求满足度（Needs Met, NM）

评估**内容对用户查询意图的满足程度**。

读取参考文件以获取详细评分标准：
- `references/pq-rubric.md` — PQ 评分细则
- `references/nm-rubric.md` — NM 评分细则
- `references/eeat-checklist.md` — E-E-A-T 评估清单

---

## 工作流程

### Step 1：理解查询意图

在评估任何内容之前，首先明确用户的原始查询：

```
查询意图分类：
├── Know / Know Simple（了解类）→ 重视信息准确性和深度
├── Do（行动类）→ 重视步骤完整性和可操作性
├── Website（导航类）→ 重视精确匹配
└── Visit-in-Person（实地类）→ 重视地理位置相关性
```

如果用户未提供原始查询，询问或从文章内容推断。

### Step 2：YMYL 判断

判断主题是否属于 YMYL（Your Money or Your Life）：

```
YMYL 检测问题：
1. 信息不准确是否会对用户造成重大伤害？
2. 是否涉及健康、财务、安全、或公共利益？
3. 是否需要专业资质才能提供准确内容？

→ 是 YMYL → 采用严格评估标准
→ 非 YMYL → 采用标准评估标准
```

### Step 3：逐篇 PQ 评估

对每篇文章按以下子维度打分：

#### 3.1 E-E-A-T 评估（0-4分）

| 分项 | 0分 | 1分 | 2分 |
|------|-----|-----|-----|
| Experience | 无亲身体验痕迹 | 有一定体验描述 | 明显深度亲历 |
| Expertise | 无专业背景 | 一般专业知识 | 领域专家水平 |
| Authoritativeness | 无任何权威信号 | 有一定引用/背书 | 被广泛认可的权威 |
| Trustworthiness | 无可验证信息 | 基本可信 | 高度透明可验证 |

#### 3.2 内容质量评估（0-4分）

| 分值 | 描述 |
|------|------|
| 0 | 无实质内容、复制内容、AI 批量生成无价值内容 |
| 1 | 低努力、低原创性、低附加值 |
| 2 | 内容尚可，但不够深入或有一定填充 |
| 3 | 高质量，准确、完整、对目标读者有价值 |
| 4 | 极高质量，独特、深入、令人满意 |

#### 3.3 网站可信度评估（0-2分）

| 分值 | 描述 |
|------|------|
| 0 | 无关于网站/创作者的可验证信息，或存在欺骗性内容 |
| 1 | 基本信息存在，声誉一般 |
| 2 | 良好声誉，有清晰的关于我们/联系方式 |

#### 3.4 Spam 检测（布尔值）

检测以下 Spam 特征（任一为真则标记为 Spam）：
- [ ] 规模化 AI 生成低质内容（Scaled Content Abuse）
- [ ] 过期域名滥用（Expired Domain Abuse）
- [ ] 站点声誉滥用（Site Reputation Abuse）
- [ ] 内容被黑客篡改
- [ ] 刻意遮挡主要内容

#### PQ 总分计算

```
PQ_score = (EEAT_avg × 0.4) + (Content_quality × 0.4) + (Site_trust × 0.2)

等级映射：
0.0 - 1.0 → Lowest
1.0 - 2.0 → Low  
2.0 - 3.0 → Medium
3.0 - 3.5 → High
3.5 - 4.0 → Highest

如果 is_spam = True → 强制降为 Lowest
如果 is_ymyl = True 且 EEAT_avg < 1.5 → 降一个等级
```

### Step 4：Needs Met 评估

对每篇文章评估其对用户查询的满足程度：

| 等级 | 标准 | 分值 |
|------|------|------|
| Fully Meets | 完全立即满足，无需查看其他结果 | 5 |
| Highly Meets | 对大多数用户非常有帮助 | 4 |
| Moderately Meets | 有一定帮助，但有明显不足 | 3 |
| Slightly Meets | 仅对少数用户有帮助 | 2 |
| Fails to Meet | 无法满足任何用户需求 | 1 |

**新鲜度调整**：
- 时事类查询：旧内容（>30天）降 1 级
- 软件/工具类：旧版本内容降 1 级
- 常青内容：无调整

### Step 5：生成评估报告

## 特殊场景处理

### 场景 A：RAG 系统召回内容评估

当用于 RAG 或 LLM Pipeline 时，输出额外的过滤建议：

```python
# 输出结构示例（JSON 格式）
{
  "query": "...",
  "is_ymyl": false,
  "results": [
    {
      "id": 1,
      "pq_score": 3.2,
      "pq_level": "High",
      "nm_level": "HM",
      "spam_detected": false,
      "recommendation": "include",
      "confidence": 0.85
    }
  ],
  "pipeline_suggestion": {
    "include": [1, 3],
    "exclude": [2],
    "overall_recall_quality": 7.5
  }
}
```

### 场景 B：单篇文章快速检测

若用户只提供一篇文章，简化输出为：
- PQ 等级 + 核心问题（3点）
- 主要 E-E-A-T 短板
- 改进建议（3条）

### 场景 C：无查询上下文的纯内容质量评估

若用户未提供查询，仅评估 PQ 维度，跳过 NM 评估，并在报告中注明。

---

## 注意事项

1. **客观性**：评估基于内容本身，不依据个人偏好
2. **地区敏感性**：考虑内容的目标地区和语言
3. **时效性**：注意内容发布日期与当前时间的关系
4. **善用疑问**：信息不足时，注明"无法验证"而非假设
5. **YMYL 从严**：YMYL 主题采用更严格标准，宁可低估不要高估
